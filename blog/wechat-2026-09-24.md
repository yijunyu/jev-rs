# 两张榜单、三个模型，结论反而更清楚了：jev-rs 与 Laya / AgentJev 对测

> **更新（09-25）：** 文末新增实验三——三个后端不再只是互相比较，而是被 `jev ensemble` 叠成一个元预测器，在 Typed Decisions 留出集上同时打败了每一个单独成员。想看"该用哪个模型"的新答案，直接跳到[第三条路](#第三条路能不能预判该用哪个模型)。

上一篇（[让大模型少"说话"、多"判断"](wechat-2026-09-21.md)）发出去之后，开源社区几乎同步给出了两个"Jev 替代品"：

- **[Laya](https://huggingface.co/convaiinnovations/laya)** —— 专为 [Typed Decisions](https://huggingface.co/datasets/LocalLLaMA/typed-decisions) 训练的系统一模型；
- **[AgentJev](https://github.com/malevrigns/agent-jev)** —— 0.6B 的 Typed Decisions 专家模型，仓库 + 权重都开源。

它们和 jev-rs 走的是**两条完全不同的路**：

| | jev-rs（logprob 路径） | Laya / AgentJev |
|---|---|---|
| 思路 | 任意 LLM 读完提示词后的下一个 token 分布，**不解码** | 整请求进、整请求出的**专用系统一模型** |
| 问题 schema | 请求时任意给 | 训练时固定的 20 个 |
| 能否零样本换题 | 能 | 不能 |

争论随之而来：到底谁更强？我们的答案是——**别猜，两边都跑一遍**。

于是把两者都接成了 jev-rs 的一等后端（`--backend-kind laya` / `agentjev`），用**同一套 `jev eval` 评测框架**，在**两份互不相干的数据集**上各跑了一轮。

## 实验一：我们的主场 —— `dev_tasks.jsonl`

25 条 shell 命令 × 3 个问题（命令类别八选一、能否安全重跑、输出量三级），75 个判断，全部 0 失败，同一台机器：

| 指标 | jev-rs（Qwen3-4B 原始 logprobs） | Laya typed-decisions | AgentJev-0.6B |
|---|---|---|---|
| 总准确率 | **0.71** | 0.49 | 0.49 |
| choice / noul / score | **0.92 / 0.64 / 0.56** | 0.68 / 0.40 / 0.40 | 0.64 / 0.40 / 0.44 |
| Brier（原始） | **0.510** | 0.586 | 0.754 |
| ECE（原始） | 0.244 | **0.102** | 0.285 |
| 延迟 p50（热） | ~90 ms | **~45 ms** | ~2 360 ms |

**读法：** 两个专用模型在**没见过的题**上准确率掉到掷硬币水平（0.49）。Laya 快 2 倍、校准后 ECE 最好看；AgentJev 在这台 CPU 上慢约 25 倍。但论"答对没有"，原始 logprob 路径明显领先。

## 实验二：他们的主场 —— Typed Decisions 测试集

同一套框架，把 [Typed Decisions](https://huggingface.co/datasets/LocalLLaMA/typed-decisions) 的 `test` 划分（400 案例 / 2000 判断，revision `ea930645…`）转成 jev-rs 的 case JSONL，再喂给三个后端：

| 指标 | jev-rs（Qwen3-4B 原始 logprobs） | Laya typed-decisions | AgentJev-0.6B |
|---|---|---|---|
| 总准确率 | 0.539 | 0.766 | **0.796** |
| choice / noul / score | 0.58 / 0.56 / 0.50 | 0.73 / 0.86 / 0.72 | **0.76 / 0.88 / 0.76** |
| Brier（原始） | 0.878 | 0.400 | **0.321** |
| ECE（原始） | 0.425 | 0.213 | **0.134** |
| 延迟 p50（热） | ~99 ms/题 | ~237 ms/案例 | ~2 687 ms/案例 |

**读法完全翻转：** 在他们自己的训练分布上，两个专家模型反超 logprob 路径 20+ 个点；AgentJev 略胜 Laya；Qwen3-4B 零样本掉到接近 prior 基线——这正是 Typed Decisions 官方文档里写的"专才 vs 通才"场景。

## 结论：不是打架，是分工

两张表放在一起，**不是矛盾，是同一枚硬币的两面**：

- **Laya / AgentJev 是专才。** 只认识训练时固定的 20 个 Typed Decisions schema。主场（Typed Decisions）上 0.77 / 0.80 大胜；换到 `dev_tasks` 这种它们从没见过的 shell 命令题，立刻掉回 0.49。
- **Qwen3-4B + 原始 logprobs 是通才。** 任何 schema 都能零样本接。`dev_tasks` 上 0.71 拿下；在 Typed Decisions 上冷启动对打"专为这份数据微调过的模型"，只能拿到 0.54——接近文档里 0.47 的 prior 基线，但**它至少还能答题**。

Typed Decisions 自己的 README 早就写过：专才和通才**不该直接比高低**。通才在固定榜上丢的那几个点，买的是"明天换一批问题照样能跑"。

### 怎么选（按流量，不按信仰）

- **问题 schema 固定、且有训好的 checkpoint** → `--backend-kind laya` 或 `--backend-kind agentjev`。主场准确率高，Laya 还更快。
- **问题会变、要零样本换题、或要嵌进现有任意 LLM 管线** → 默认的 `llamacpp` / `openai` logprob 路径。输出恒为 0 token，情境只 prefill 一次。
- **都要** → 第三条路：`jev ensemble`，见下。

没有"全面碾压"的那一个。**每个路径都在自己被造出来的那个场景里赢。**

## 第三条路：能不能"预判该用哪个模型"？

有读者问了一个很自然的问题：模型 X 做完 prefill 之后，能不能**预测**出"这题该由模型 Y 来解码"，然后把 X 的 logits 直接复用给 Y？

答案分两半，都值得说清楚：

1. **logits 本身不能跨模型复用。** X 的 logits 活在 X 自己的词表和隐状态几何里；Y 是另一套权重、另一种（甚至不同的）tokenizer，X 的 logits 对 Y 没有意义——哪怕同属一个家族（比如 Qwen 0.6B 和 4B），隐层维度都对不上，谈不上"把 X 的隐状态接到 Y 的 LM head 上"。所以**不存在**"用 X 的 prefill + Y 的解码"这种拼接。
2. **能复用的是概率向量。** 三个后端虽然内部千差万别，但对外都输出"同一批选项标签上的分布"——这是它们唯一的公共表示。于是可以退一步：不追求复用 X 的 logits，而是训练一个**元预测器（stacker）**，输入是"所有成员对这题的概率向量"，输出是最终答案。它本质上在学"什么时候该信谁"——这正是"预判该用哪个模型"的诚实版本：不是挑一个 Y 跑一遍，而是让一个小逻辑回归替你把票投了。

这就是新命令 `jev ensemble`：把每个后端的 `jev eval --rows` 文件喂进去，按**案例级**划分（同一案例的题不会同时进训练集和测试集，杜绝泄漏）拟合一个多项逻辑回归 stacker，测试集上的数字和每个成员、以及"三者均匀平均"并排输出——还是同一套 `eval::metrics`。

### 实验三：三个臭皮匠（Typed Decisions test，540 题留出集）

| | 准确率 | Brier | ECE |
|---|---|---|---|
| llamacpp Qwen3-4B（logprob 路径） | 0.548 | 0.540 | 0.082 |
| Laya typed-decisions | 0.778 | 0.301 | 0.038 |
| AgentJev-0.6B | 0.811 | 0.264 | 0.018 |
| 三者均匀平均 | 0.800 | 0.299 | 0.125 |
| **stacker（三者全部）** | **0.822** | **0.253** | 0.043 |

**读法：stacker 在准确率和 Brier 上打败了每一个成员**——包括那个单独只有 0.548 的通才。也就是说，弱成员的概率向量里仍然携带两个强专家看不见的信息，元预测器把它榨出来了。ECE 0.043 略逊于 AgentJev 单打的 0.018，但准确率换来的那一分是实打实的。

两个诚实的脚注：

- **`dev_tasks` 上 stacker 赢不了。** 那个留出集只有 12 题，llamacpp 单打 0.833——成员本身已经快对完了，没有可学的余地。集成效应需要大样本才看得出来。
- **延迟是三个成员之和**（三个后端都要跑，报告里如实标注）。所以 ensemble 不是"免费的午餐"，它买的是准确率，付的是三倍推理——要按流量算账。

## 复现

三个后端全部走同一条命令形态，结果文件就是 README 里那两张表：

```sh
# 主场（dev_tasks）
jev --backend http://127.0.0.1:8089 eval examples/dev_tasks.jsonl
jev --backend http://127.0.0.1:8010 --backend-kind laya --model typed-decisions \
    eval examples/dev_tasks.jsonl
jev --backend http://127.0.0.1:8149 --backend-kind agentjev \
    eval examples/dev_tasks.jsonl

# 客场（Typed Decisions test，已转成同格式）
jev --backend http://127.0.0.1:8089 eval examples/typed_decisions_test.jsonl
jev --backend http://127.0.0.1:8010 --backend-kind laya --model typed-decisions \
    eval examples/typed_decisions_test.jsonl
jev --backend http://127.0.0.1:8149 --backend-kind agentjev \
    eval examples/typed_decisions_test.jsonl

# 第三条路：把三个后端的 rows 叠成一个 stacker（案例级划分，报告自动输出留出集指标）
jev ensemble --rows td_llamacpp.rows.jsonl --rows td_laya.rows.jsonl \
             --rows td_agentjev.rows.jsonl --out ensemble.json
# 之后可直接套用已拟合的模型（成员顺序必须一致）
jev ensemble --model ensemble.json --rows … --rows … --rows …
```

代码、后端适配器（`src/backend/systemone.rs`、`src/backend/agentjev.rs`）、stacker（`src/ensemble.rs`）和三张对比表都在 [github.com/yijunyu/jev-rs](https://github.com/yijunyu/jev-rs) 的 README 里，欢迎自己复跑、打脸、或者把你领域的 case 交过来。
