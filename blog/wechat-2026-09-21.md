# 让大模型少"说话"、多"判断"：jev-rs 与去解码的系统一决策

## 先说"系统一"

心理学家卡尼曼把人的思维分成两套系统。**系统一**是直觉：看到一封邮件，你不用逐字推理就知道"这是催款的"、"这人要走了"。**系统二**是慢思考：一步一步推导、写下理由。

今天的大模型几乎全在用系统二的方式工作。哪怕只是问它"这条 shell 命令会不会有副作用？"，它也要先吐出一段解释，再给出结论，然后我们还得把结论从一堆文字里解析出来。每个吐出来的 token 都要钱、都要时间，而我们真正需要的只是一个 **是/否**、一个 **类别**、一个 **等级**。

九月中旬，TypeSafe AI 发布了 Jev，号称第一个"系统一模型"：只回答**类型化的问题**，返回概率而不是文字。一次请求带上"情境"和若干问题，几百毫秒内返回全部判断。这个思路很对，但 Jev 是闭源的托管服务。

## jev-rs：用任何本地模型做"直觉"

**jev-rs** 是我们开源的一个 Rust 实现（MIT / Apache-2.0）。它的想法非常朴素：

> 大模型在读完提示词之后，下一个 token 的概率分布本身就是"直觉"。我们只读这一层 logits，**不解码**。

具体做法：把情境放进共享前缀，每个问题作为后缀，选项标成 A、B、C……，提示词以 `Answer:` 结尾。然后只看紧接着那一个位置上 A、B、C 各自的对数概率，做一次受限 softmax，就得到了带概率的答案。

- **输出 token 永远是 0。** 没有推理链、没有 JSON 需要解析、不会"幻觉"出选项之外的东西。
- **情境只预填一次。** 同一个情境下问四个问题，只付一次完整 prefill，后面三个问题各只增加几十个 token。
- **兼容 Jev 的接口。** 官方 SDK 把 `TYPESAFE_BASE_URL` 指向本地就能用；同时提供 MCP 工具，Claude Code、Codex、Grok Build、OpenCode 都能直接调用。
- **任何 GGUF 模型。** 目前后端是 llama-server，模型随便换。

一行安装：

```
curl -fsSL https://raw.githubusercontent.com/yijunyu/jev-rs/main/install.sh | sh
```

或者 `cargo install jev-rs`。仓库：github.com/yijunyu/jev-rs。

## 目前测到了什么（诚实版）

在一台 M1 Ultra 上跑 Qwen3-4B 的 4-bit 量化版，零样本，不做任何微调。25 条 shell 命令，每条问三个问题（命令类别八选一、能否安全重跑、输出量大不大），共 75 个判断：

| 指标 | 结果 |
|---|---|
| 八选一命令类别准确率 | 0.92 |
| 是/否（能否安全重跑） | 0.64 |
| 三级评分（输出量） | 0.56 |
| 每个问题延迟中位数 | 75 ms |
| 四个问题一次请求 | 394 ms |

结论很清楚：**分类这类问题它做得不错，而且便宜；涉及安全性的是非判断还不能交给它。** 另外 4B 的指令模型出厂时极度自信，概率必须先在自己的数据上做温度校准（工具里带了 `jev calibrate`），否则概率没法当概率用。

## 还有很多未知

- 26 个选项以上单字母标签就不够了，要做分层选择。
- 不同模型的直觉质量差别很大，还没系统比较。
- 概率校准之后到底能不能用来做"不确定就交给人"的门控，需要更多真实数据。
- 更深的一步——把推理引擎本身改成"只做 prefill、按问题分叉 KV 缓存"的判断引擎——才刚开始。

## 邀请：软件工程里哪些动作可以"不解码就决定"？

我们最关心的用途是**给编程智能体省 token**。一个 Claude Code 会话里，大量决策其实是系统一级别的：这条命令属于哪一类、这段工具输出要不要整段塞进上下文、这次改动该唤起哪个技能、这个 diff 需不需要跑全量测试、这个 PR 该先给谁看。每一个今天都在用大模型"慢想"，每一个都可能变成一次 75 毫秒、零输出 token 的直觉。

如果你在做智能体、CI、代码审查工具，欢迎来一起试：

1. 用 `examples/dev_tasks.jsonl` 的格式贡献你领域的判断题和标注；
2. 接一个新的后端（llama.cpp 进程内、ds4-rs-metal、任何暴露 logits 的引擎）；
3. 把它挂进你的智能体钩子，量一量到底省了多少 token，把数字发回来。

慢思考留给真正需要推理的地方，直觉交给 logits。这件事能走多远，我们也不知道，所以才开源。
